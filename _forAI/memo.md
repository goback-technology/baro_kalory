## 제품 기준선

- 대상: PTZ CCTV 커미셔닝 콘솔 웹 UI. 배포 형태는 **정적 사이트**.
- 런타임 의존: React·React DOM. 빌드 의존: Vite·Tailwind CLI.
- 버전 출처: `package.json` 과 `public/app-versions.json`. 문서에 숫자를 복사하지 않는다.

## API 주소 주입

이 저장소에는 **백엔드가 없다.** 화면이 쓸 API 주소는 런타임에 정해진다.

우선순위: `?api=` 쿼리 → localStorage(설정 화면) → `<meta>` → **미설정**. **기본값은 없다.**

- `?api=` 는 **URL 에 남는다**(저장되지 않는다). 주소에 있는 동안은 그 백엔드만 보이므로,
  되돌리려면 쿼리를 지운다.
- **`?api=reset` 이 탈출구다.** 잘못된 주소를 **저장해** 화면이 벽돌이 되면 설정 화면조차 못
  여는데, 이 쿼리가 저장된 base 를 지우고 스스로 URL 에서 빠진다(`src/lib/api.mjs`). 정적 파일은
  base 와 무관하게 항상 뜨므로 이 길은 언제나 열려 있다 — 모르면 캐시·브라우저 데이터를 뒤지게
  된다.
- 스킴 없는 주소(`호스트만` 입력)는 fetch 가 상대경로로 해석해 화면이 벽돌이 된다 — 입력
  정규화가 스킴을 보정한다.
- **추측하지 않는다.** 한때 "같은 마운트에 백엔드가 있겠거니" 하고 자기 오리진을 기본값으로
  삼았는데, 두 가지가 무너졌다: (1) 분리 배포에서는 그 추측이 틀린 쪽이 정상이고, (2) 설정
  화면의 「초기화」를 눌러도 추측이 즉시 자리를 메워 **지워졌는지 화면으로 구분할 수 없었다.**
  지금은 미설정이면 미설정으로 둔다.
- 미설정이거나 백엔드가 무응답이면 `src/app/backend-gate.jsx`가 **게이트**를 띄운다 — 원인을 갈라 말하는
  배너 + 설정·대문을 뺀 바로가기 잠금. 200 이어도 버전 필드가 없으면 연결로 치지 않는다
  (엉뚱한 서버의 200 을 연결로 오인하면 화면만 열린 채 전 기능이 조용히 죽는다).
- **어떤 백엔드 주소도 저장소에 박지 않는다.** 공개 저장소이고, 박는 순간 내부망 사실이
  이력에 영구 기록된다.

## 카메라 제어 인증과 lease

- 인증 상태의 출처는 `GET /api/control/identity`다. `features.cameraScoped`가 참일 때만
  카메라 기능 요청을 `/api/cctv/devices/:cameraId/...`로 보낸다. 기능 협상 실패는 그대로
  오류이며 **404만** 구형 계약 폴백이다. 버전 문자열을 비교하지 않는다.
- `src/lib/control-session.mjs`는 완전한 API base(오리진+마운트)별로 sessionStorage에 토큰을
  저장한다. URL·localStorage에 복사하지 않는다. 같은 API 마운트 내부 fetch에만 Bearer를
  붙이고 자격증명 포함 요청의 리다이렉트는 거절한다. 이미지·EventSource에는 토큰을 URL로
  옮겨 붙이지 않는다. 이 읽기 경로의 접근 통제는 백엔드·배포 계약의 몫이다.
- 수동 이동 직전에 persistent lease를 획득한다. 한 카메라의 동시 획득은 같은 Promise를
  공유하며, 만료가 5초 이내이면 갱신한다. 401·409에서 폐기한 lease로 이동을 재전송하거나
  자동 재획득하지 않는다. 명령 실행 여부와 우선순위는 서버만 판정한다.
- 호밍·캘리브레이션·높이 작업 시작에는 이 탭의 기존 lease를 함께 보내고 성공 시 캐시에서
  제거한다. 이는 서버의 수동 점유→작업 점유 전환이며, UI가 별도 소유자를 만들지 않는다.
- 카메라 전환·컨텍스트 재생성 전에는 스트림과 수동 lease를 놓는다. 선택 세대가 달라진
  대기 중 요청은 보내지 않으며 늦게 돌아온 GET 응답도 폐기한다. 다른 탭의 활성 변경은
  visibility 재조회에서 React 상태·제어 대상까지 함께 갱신한다.
- 공통 상태줄은 수동 소유자·작업·복구 필요를 표시한다. 이 탭의 수동 lease만 반납 버튼을
  제공하고 작업 중지는 각 작업 화면에서 한다. `recovery_required`의 재시도는 서버가
  `canRetry:true`라고 답할 때만 제공한다. 조회 실패를 유휴 상태로 바꾸지 않는다.
- 사용 기록은 `after` 커서가 배타적인 카메라별 감사 조회다. 오래된 순서로 25개씩 이어 읽으며
  최신 기록을 본다고 표시하지 않는다. 로그·토큰 원문을 화면 문서나 저장소에 복사하지 않는다.

## 내장 analytics와 ONI 프레임 대응

- `analytics/events` SSE의 검출은 동일 `cameraId`·`streamEpoch`·`frameId`의
  `analytics/frames/:frameId` JPEG와만 짝지어 표시한다. JPEG를 읽는 동안 들어온 메타데이터는
  최신값으로 합치며, 프레임 캐시의 404·410은 다음 검출을 기다린다.
- 박스 좌표는 검출의 `image.width/height`다. 영상 로드 후 실제 크기까지 일치해야 겹친다.
  일반 프리뷰의 1920×1080 논리 프레임에 대응시킬 수 없다. 같은 패킷의 영상·결과이지
  카메라 내부 촬영·추론 시각의 정확한 동기화까지 검증한 것은 아니다.
- 중지·카메라 교체·스트림 epoch 변경 후 늦게 도착한 JPEG는 폐기한다. Blob URL은 교체와
  destroy에서 반환한다. 탭이 숨겨지면 구독을 중지하며 다시 보인다고 자동 재시작하지 않는다.
- ONI 분석은 **현재 표시된 Blob**을 고정해 `/api/inference/vehicle-det`에 보낸다.
  별도 snapshot을 읽으면 화면과 분석 대상이 달라지므로 이 경로에서는 호출하지 않는다.
- 미지원·꺼짐·메타데이터 대기·재연결·결과 지연·오류를 분리한다. 과거 검출은 age와 stale
  표시를 남기며 실시간 결과처럼 표현하지 않는다.

## GitHub Pages 제약

Pages 는 **재작성 규칙이 없는 순수 정적 호스트**다. 다음이 전부 불가능하다.

- 확장자 없는 URL(`/cctv` → `cctv.html` 재작성) · 디렉터리 진입 시 index 자동 선택 외의 규칙
- 리버스 프록시 — 그래서 API 는 반드시 **교차 출처**가 된다
- 서버측 헤더 제어 · 리다이렉트 규칙

따라서:

- 배포 산출물은 `pnpm build:dist`가 만드는 dist다. Vite가 SPA 셸과 번들을 만들고
  `build/vite-kalory.mjs`가 옛 `.html` 주소용 리다이렉트 셸을 발행한다.
- **CORS 는 백엔드가 허용해야 한다.** 이 저장소가 고칠 수 있는 문제가 아니다.
- **혼합 콘텐츠**: Pages 는 https 다. 백엔드가 http 면 브라우저가 요청을 차단한다.
  사설망 http 백엔드를 https 페이지에서 부르는 조합은 성립하지 않는다.
- Pages 의 base path 는 **저장소 이름**이다. 절대경로로 자산을 참조하면 하위 경로에서 깨진다.

## 런타임 구조 메모

- 페이지 목록의 단일 출처는 `src/app/routes.mjs` — 헤더 nav·버전 배지·홈 카드가 전부 이 표를 본다.
- 테마는 `<html data-theme>` + CSS 변수 토큰. 색·글꼴·반경을 하드코딩하면 테마 교체가 깨진다.
- 버전 표시는 `public/app-versions.json` 을 페이지가 **직접** 읽는다. 백엔드가 대신 읽어 주면
  프런트만 배포한 순간 거짓말이 된다.

## 캘리브레이션 — 발행·적용·해제·삭제

2026-08-18 확정. 백엔드가 두-사본 설계를 버렸다(팀 보드 #61). 이 저장소가 지켜야 하는 것들.

- **발행이 곧 적용이다.** 문서(`localfiles/profiles/camera/<id>/rev-NNNN`)가 유일한 산출물이고
  `config.json` 에는 아무것도 안 쓴다. 백엔드 **0.17.0** 부터 드라이버가 광학을 **읽는 시점에**
  해결하므로, 발행하면 다음 조준이 새 곡선을 쓴다 — 재시작도 기기 재선택도 없다(보드 #71).
  **그 이전 백엔드는 부팅과 기기 재선택 때만 읽는다.** 거기서 발행만 하고 멈추면 카메라는 옛
  곡선으로 계속 조준하는데 **증상이 없다** — 정상적으로 답하는데 숫자만 틀리다.
- **버전으로 갈래를 고르지 않는다 — 응답의 `reload` 를 읽는다**(`applyPublishedToRuntime`).
  백엔드가 「더 할 일이 있는가」를 스스로 답한다(0.16.6+:
  `{restartRequired, reload:{required, applied, note}}`). `required` 가 `false` 면 **아무것도 하지
  않는다.** 그 블록이 없는 옛 백엔드에서만 `POST /api/cctv/active {id, force: true}` 로 재선택하고,
  거기서는 **`force` 가 필수다** — 같은 id 를 그냥 보내면 `{unchanged:true}` 로 튕기는데 그게
  **200** 이라 성공한 것처럼 보이고 버려진다. 이 함정 때문에 재시작이 유일한 길처럼 보였고,
  화면이 20분 스윕 끝에 사람을 pm2 로 보냈다. **`pm2 restart` 를 안내하지 않는다.**
  0.17.0 에서 재선택은 불필요할 뿐 아니라 **해롭다** — 기기 컨텍스트를 다시 지으면서 스윕 결과를
  쥔 캘리브레이션 매니저가 갈아치워진다. **두 계약이 지금 동시에 살아 있다** — 개발기는 새
  계약, 배포기는 옛 계약이다(버전 숫자는 여기 적지 않는다. `/api/health` 가 출처다). 응답을
  읽으면 옛 계약이 사라질 때 옛 갈래가 저절로 죽는다.
- **`reload.applied` 를 `required` 와 따로 읽는다.** 「할 일 없음」과 「조준이 바뀌었음」은
  **이미 갈라졌다**(0.18.0 의 고정·해제, 보드 #73) — 고정·해제 중에는 발행해도 조준이 안 바뀌고
  `reload.applied:false` + 사유로 온다. 이유는 백엔드만 아니까 `note` 를 **그대로** 옮긴다.
  우리가 지어내면 백엔드가 바뀔 때마다 화면이 조용히 거짓말을 시작한다.
- **`apply` 는 적용 포인터를 쓴다**(0.18.0 부터. 그전에는 확인 전용이었고 옛 리비전은 409 였다).
  `{revision:N}`=고정(**옛 리비전이 합법이다** — 없는 리비전만 409) · `{revision:null}`=해제 ·
  `{follow:true}`=최신 따름 복귀 · `{}`=확인. **되돌리기는 고정으로 한다** — 재발행(`copy`)은
  이력에 사본을 늘리므로, 포인터가 없는 옛 백엔드에서만 쓴다. 「그 결정을 이력에 남기고 싶다」가
  이유일 때만 새 리비전을 만든다.
- **"이 카메라가 캘리브레이션돼 있나"를 `config.devices[].intrinsics` 로 판정하지 않는다.**
  발행이 거기에 쓰지 않으므로 **거짓 음성**이 된다(실제로 그랬다 — 적용된 카메라를 두고
  「없습니다」라고 말했다). 정본은 `GET /api/help?format=json` 의 `live.optics` 다. 서버가 매
  요청 계산하므로 그쪽이 이긴다.
- **`intrinsics` 는 찌꺼기가 아니라 씨앗값이다 — 지우게 두지 않는다.** 스윕이 줌 앵커를 잡는 데
  쓴다. 벤더마다 줌 눈금이 달라(IDIS 는 배율 ×100, 100..1200) 지우면 남의 눈금으로 앵커를 양끝에
  몰아 놓고도 **rc=0 으로 끝난다** — 측정된 것처럼 보이는 표가 남는다.
- **삭제(DELETE, 백엔드 용어 retire)가 언제 반영되는지는 계약마다 다르다 — 예측하지 말고 읽는다.**
  화면 표기는 **「삭제」**다 — 백엔드의 retire/.trash 는 서버 관리자의 사정이고, 작업자에게는
  목록에서 사라지고 화면으로 못 되돌리면 그것이 삭제다(「퇴역」 표기가 삭제 방법을 못 찾게 했다). 0.17.0 은 다음
  조준부터 config 씨앗값으로 내려앉고, 그 이전은 재선택·재시작 뒤부터다. 화면이 시점을 미리 적어
  두면 백엔드가 바뀔 때 조용히 거짓말이 된다(하루 만에 두 번 바뀌었다). 되돌리는 길은 API 에
  없다 — `.trash` 복구 라우트가 없다.
- **`live.optics.declared` 한 칸으로 판정하지 않는다.** declared 는 「발행본이 적재됨」과
  「씨앗값이 광학을 제공함」을 구분하지 못한다 — 씨앗값 있는 기기는 퇴역 직후에도 `true` 다
  (2026-08-19 ref-ptz 실측: 「아직 옛 곡선」·「발행본이 적용돼 있습니다」 거짓말 둘이 이 칸에서
  나왔다). **1차 판정은 `live.optics.source`**(`published`|`seed`|`none`)와 함께 오는
  `revision`·`following`·`detached` 다(0.18.0 부터). 삭제 응답도 `runtimeOptics:
  "seed-at-next-read"` 로 답한다. 그 필드가 없는 **옛 백엔드에서만** 우회로 내려간다 —
  삭제 전후 `live.optics` 비교(`opticsSnapshot` → `retireEffect`)와, 「발행본 적용」 주장에
  붙이는 발행본 존재 재조회(`/profiles/camera/:id/revisions`, 404 는 「확실히 없음」)다.
- **프로파일 쓰기는 언제나 헤더의 활성 카메라를 대상으로 한다.** 왼쪽 목록은 **모든 카메라의
  카탈로그**라, 목록에 보이는 남의 발행본을 보고 삭제를 누르면 활성 카메라 기준으로 나가 404 로
  실패하고 목록에는 그대로 남는다("지웠는데 남아 있다"의 원인). 발행본 없는 카메라에서는 삭제·
  되돌리기를 **잠그되 404 일 때만** — 일시 읽기 실패로 버튼이 죽으면 그게 더 나쁘다.
- **드리프트 판정은 백엔드가 한다.** 화면은 `GET /api/help?format=json` 의 `live.profileDrift`
  문장을 **그대로** 옮긴다 — 브라우저에서 곡선을 다시 비교하면 두 번째 구현이 생기고, 두 구현은
  언젠가 서로 다른 답을 낸다(이 카드가 없애려는 병이 정확히 그것이다). 0.17.0 이후 이 판정은
  드리프트 감시가 아니라 **배선 자기점검**이다 — 말을 하면 광학 주입이 깨진 것이다.
- **장기 작업은 시작 시점 곡선을 끝까지 쓴다**(캘리브레이션 스윕 · 번호판 호밍). 앞뒤 샘플이 다른
  모델에서 나오면 잔차가 의미를 잃기 때문이고, 이건 의도된 예외다 — 스윕 도중 누가 발행해도 그
  스윕은 안 흔들린다. 「읽는 시점에 해결」은 **살아 있는 읽기**에만 적용된다.
- **백업은 없고, 만들지 않는다**(보드 #76, 이교수님 결정). 프로파일은 카메라가 아니라 **그 순간의
  리그 상태**를 적은 문서다 — 카메라를 다시 달거나 렌즈를 바꾸면 바이트는 그대로인데 아무것도
  설명하지 못한다. 백업 기계의 실제 기능은 곡선을 「참이 아니게 된 경계」 너머로 나르는 것이라,
  그게 #61 이다. **잃어버린 프로파일의 답은 다시 재는 것이다.** 복원 UI 를 만들지 않고, 발행본이
  없으면 「재측정」으로 표시한다. 리비전 이력을 **보는** 것은 추적성이라 정당하다 — 물리적 변경을
  건너뛰어 **적용**하는 것이 오류다.

### 스윕 화면

- **`status.recent[]`** 가 마지막 6표본을 준다 — `{zoom, dx, dy, residualX, residualY, peak,
  margin, usable}`. 진행률만 세지 말고 이걸 그린다. 20분 독점 작업에서 "도는 중"과 "굳음"을
  가르는 유일한 신호다.
- **0.18.0 부터 적용 포인터가 있다**(보드 #73). `apply {revision:N}`=고정(옛 리비전 합법) ·
  `{revision:null}`=적용 해제(다음 읽기부터 씨앗값) · `{follow:true}`=최신 따름 복귀 · `{}`=확인.
  상태는 revisions 응답의 `applied` 와 `live.optics` 의 `source·revision·following·detached` 로
  온다 — 4-상태: 최신 따름 / 고정 / 해제(detached) / 미발행(revision null + following, 해제 아님).
  **핀·해제 중 발행은 문서만 쓰고 `reload.applied:false` + 사유**로 답한다(appliedSuffix 가 그대로
  옮긴다). **고정 중 DELETE 는 409 `pinned`** — 해제 후 삭제가 백엔드 규칙이다. 옛 리비전 복귀는
  재발행(copy)이 아니라 **고정**으로 한다 — 이력에 사본이 늘지 않는다(포인터 없는 옛 백엔드만 copy).
- **0.19.0 부터 검증 판정은 「구간 대 문턱」이다**(보드 #95). 줌마다 자기 게이트
  `thresholdPx = max(10px, f(z)·tan(0.040°))` 와 신뢰구간 `ciAbsPx{lo,hi}` 가 오고, 구간이
  게이트에 걸치면 `inconclusive`(+`reason: noise|few_samples`) 다. **판정값은 다섯이다** —
  `pass` · `fail` · `inconclusive`(측정 한계) · `incomplete`(못 잰 줌이 있음 — `unmeasured[]`,
  **장면 문제**다) · `unknown`. 집계는 최악 우선(`fail` > `incomplete` > `inconclusive` >
  `pass`). **`inconclusive` 와 `incomplete` 는 처방이 다르다** — 앞은 표본을 늘리거나 그
  설치의 산포를 받아들이는 것이고, 뒤는 밝을 때 다시 재는 것이다. **논리 분기는 `certified`
  불린 하나만 쓴다** — `verdict !== "fail"` 은 판정 보류를 성공으로 삼키는 버그다. 헤드라인
  숫자는 `worstOverGate`(자기 줌 기준의 배수) — 23배 화각 범위에서 픽셀 원값 비교가 #95 의
  병인이었다. `calibration: "none"` 이면 「미보정 상태 측정」 캡션을 먼저 붙인다 — 보정 전
  기록의 fail 이 카메라 불량으로 읽히면 비교 시연의 before 절반이 빨간 경고로 덮인다.
  `inconclusive/noise` 와 #92 의 `settleWarn: timeout` 은 같은 물리적 사실(좁은 화각에서
  화면이 안 멈춤)의 두 얼굴이다 — 한 이야기로 그린다.
- **0.17.1 부터 표본마다 `settleMs`·`settleWarn` 이 실린다**(보드 #92 — 진동 안정화 게이트).
  `settleWarn` 은 정상이면 없음, `timeout`(1px 안으로 못 멈춤 — **가장 조용한 순간의 프레임**을
  사용, 고배율에서는 바람·구조물 때문에 정상) · `unmeasurable`(패턴 부족) · `undecodable`.
  HUD 에 그리되 **timeout 에 고장 색을 칠하지 않는다** — 설치 환경의 속성이지 사고가 아니다.
  고배율 스윕은 표본당 2~5초씩 길어진다(전체 약 +5분) — 진행이 느린 것이지 굳은 게 아니다.
- 좌표는 언제나 **1920×1080 논리 프레임**. 오버레이는 `viewBox="0 0 1920 1080"` 하나로 겹치고
  `naturalWidth` 를 읽지 않는다 — 그래서 스테이지를 16:9 로 못박는다.
- **잔차를 확대해 그리면 배율을 화면에 적는다.** 합격선이 10px 이라 실척으로는 안 보이는데,
  말없이 부풀린 그림은 거짓말이다. 허용 원도 **같은 배율**로 그려야 합·불이 눈으로 갈린다.
- `usable` 이 없을 때 성공으로 단정하지 않는다. `recent[]` 모양은 백엔드가 바꿀 수 있다.

## 개발기 상주 (pm2)

`ecosystem.config.cjs`의 현재 앱 이름은 **`kalory-dev`**다. Vite를 개발기에서 상주시키는
편의이며 배포는 정적 호스트가 담당한다. 아래 2026-08-17 실측의 `calory-ui`는 당시 이름이다.

- **설정값을 ecosystem 파일에 두지 않는다. `.env` 가 유일한 출처다.** pm2 는 **등록 시점의
  환경 전체를 스냅샷해 매 기동에 다시 주입**하므로, 스냅샷에 `BARO_*` 가 들어가면 `.env` 를
  고쳐도 안 듣는다. `--update-env` 는 *현재 셸*을 다시 읽는 것이라 도움이 안 된다. 증상이
  고약한 것은 **어떤 키는 먹고 어떤 키는 안 먹어서 캐시 버그처럼 보이는** 점이다(팀 보드 #56 —
  형제 프로젝트 dwarf 가 이걸로 한 시간을 썼다. 그쪽은 ecosystem 에서 `dotenv.config()` 를
  부르는 구조라 스냅샷에 값이 들어간다).
- 여기서는 스냅샷을 비워 뒀으므로 **`.env` 수정 → `pm2 restart kalory-dev` 로 반영된다.**
  실측(2026-08-17): `pm2 jlist` 의 `pm2_env` 에 `BARO_*` 없음 확인 → `BARO_BACKEND_URL` 을
  더미로 바꿔 재시작 → 기동 로그가 더미를 찍음 → 원복 후 재시작 → 원값 복귀·`/api/version` 200.
  **파일이 아니라 프로세스를 본다** — `pm2 jlist` 의 `pm2_env.<KEY>` 가 정본이다.
- **`ecosystem.config.cjs` 를 고쳤을 때는 restart 로 안 된다.** pm2 가 실행 중 항목에 설정을
  캐시한다 → `pm2 delete kalory-dev` → `pm2 start ecosystem.config.cjs` → `pm2 save`.
- **`.mjs` 는 pm2 의 확장자→인터프리터 매핑에 없다.** `interpreter: 'node'` 를 비워 두면
  호스트에 따라 즉사한다.
- **Windows 에는 부팅 훅이 없다.** `pm2 startup` 은 `Init system not found`(Startup.js:216)로
  실패한다 — systemd/upstart/launchd 전용이다. 작업 스케줄러·Run 키·서비스 어디에도 항목이
  없으므로 `pm2 save` 는 덤프를 쓰기만 하고 아무도 읽지 않는다. 재부팅 뒤 **`pm2 resurrect`
  를 손으로** 부른다(이교수님이 자동화 대신 수동을 택했다, 2026-08-17).
- `pm2 list` 의 `status=online` 만 믿지 않는다 — 크래시 루프 중에도 online 이다. `↺`(재시작
  횟수)가 오르는지와 실제 응답(`/api/version`)으로 판정한다.

## 동작 규칙

- **스트림 전환은 이전 stop 을 await 한 뒤.** 안 하면 연결이 전환마다 누적돼 스트림이 저하된다.
- **프리뷰는 열자마자 시작하지 않는다.** 페이지를 여는 행위가 카메라 점유가 되면 안 된다 —
  시작/정지로만 켜고 그 선택을 기억한다(기본 꺼짐).
- **일반 프리뷰의 박스·클릭 좌표는 1920×1080 논리 프레임.** 내장 analytics 패널은 검출의
  `image.width/height`와 대응 JPEG를 사용하는 별도 계약이다.
- **정적은 `Cache-Control: no-cache`.** "API 는 되는데 브라우저만 안 됨"은 대개 캐시다.
- **연결 수명 전달.** 브라우저가 끊으면 업스트림도 즉시 끊어야 한다. 안 하면 유령 시청자로
  남아 카메라를 영구 점유한다.

## 시뮬레이터 인스턴스 계약 (다중 실행)

2026-08-15 확정(이교수님). 시뮬레이터(`baro_unreal`) 인스턴스의 **기동·포트 부여·헬스체크·재시작은
에이전트가 관리**한다 — 시뮬 쪽에 자동 포트 탐색은 의도적으로 없다.

- **계약**: 기동 `baro_unreal.exe -ScenePort=N`(플러그인 v0.1.16~, Shipping 포함 전 빌드 구성) →
  준비 확인 `GET :N/scene/catalog` 200 → 실패/종료 감지 = 프로세스 exit.
  포트 충돌이면 시뮬이 **스스로 즉시 종료**하므로, **프로세스가 살아 있으면 포트는 보장된다**
  (엉뚱한 포트·localhost 반쪽 기동 같은 제3의 상태 없음). 포트 대장의 진실은 에이전트 쪽이다.
- **인스턴스별로 분리할 것**: `simulator.port`(=ScenePort)와 devices 카메라 포트 블록 전부.
  카메라를 DELETE 해도 그 HTTP 리스너는 시뮬 프로세스 종료까지 남아(UE 엔진 제약) **다른
  인스턴스가 그 포트를 재사용할 수 없다.**
- **자원 한도**(실측): 인스턴스당 유휴 RAM 4.0GB / VRAM 2.2GB — 8GB GPU 기기는 2개가 실용 한도.
- 상세 계약은 실행 중인 sim 이 직접 서빙한다: `GET /scene/help` 「인스턴스 기동·포트 계약」.
  구 배포본(플러그인 ≤0.1.15)엔 스위치가 없다 — `-UserDir` 우회는 `baro_unreal` `_forAI/memo.md` 참조.

## 반복 금지

- **공개 저장소에 내부망 사실을 커밋하는 것.** 사설 IP·실기 호스트명·계정명·사내 도메인.
  주석과 테스트 픽스처가 특히 잘 빠져나간다 — 눈에 안 띄기 때문이다.
- **타입/기기 이름을 프런트에 박는 것.** 개명 한 번에 죽은 분기가 된다. 서버 응답의 메타로
  판정한다(실제로 그래서 기기를 추가·저장할 수 없던 전례가 있다).
- **광학 기본값으로 빈 응답을 메우는 것.** 없는 값을 기본 곡선으로 채우면 조용히 틀린 곳을
  그린다. 없으면 없는 대로 처리한다.
- **라우팅 정의를 여러 곳에 미러해 두고 한 곳만 고치는 것.** 정적 호스트에서는 이것이 곧
  404 다 — 미러 지점을 `inventory.md` 에 명시하고 함께 고친다.
